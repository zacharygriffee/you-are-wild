## Important Current UI Doctrine

The intended north-star model is:

- Story layer: read-only semantic/presentation output.
- Stage layer: 3x3 world/traversal surface and local presence.
- Composer layer: `Actor(s) -> Target(s) -> Intent`.
- Drawer layer: details, management, inventory, stats, map review, quests, logs.

For mobile:

- Presentation stays at the top.
- The 3x3 play surface is primary movement.
- Controls belong near the bottom/dock.
- Full Party/Creatures panels should be details/management, not required for normal interaction.

For desktop:

- Center should stay presentation/stage/composer.
- Side panels can stay visible, but default cards should stay compact.
- Full details should be opt-in.

## Known Recent Issue

User reported that Chrome DevTools mobile emulation shows the play area taking about half the screen, while the real phone does not.

Investigation result:

- This is not exclusively a DevTools rendering bug.
- It reproduces in headless Chromium at a DevTools-like viewport (`313x670`).
- Cause is mobile CSS:
  - `.mobile-play-surface` uses `min-height: 100%`.
  - `.mobile-map-card` uses `flex: 1 1 auto`.
  - The map card absorbs leftover vertical space.
- On real phones this may be less visible because the effective viewport is taller or browser UI changes `dvh`.

Recommended future fix:

- Cap mobile exploration map height with a responsive `max-height`/`clamp()`.
- Avoid letting `.mobile-map-card` absorb all leftover height.
- Preserve real-phone feel; do not overcorrect solely for DevTools.

Relevant CSS area:

- `app/template.html`, mobile media query around `.mobile-play-surface`, `.mobile-map-card`, `.mobile-scene-sheet`, and `.mobile-panel-dock`.
